# 用户验证计划（尚未执行）

## 招募与同意

计划邀请5位完成过一轮基础学习的自学者，确保至少两位主要使用手机。当前没有已招募的受访者。说明作品是原型、题目为样例、可随时退出、不评估其个人能力；观察记录需取得同意。不记录账号、完整屏幕或个人真实备考历史。

## 约20分钟任务脚本

1. 不介绍功能，让体验者从空总览开始，观察是否能独立提交第一题。只记时间与受阻点，不暗示答案。
2. 问「现在你觉得下一题为什么是这题？」记录其原话，不先给定义。
3. 在明确虚构数据后加载演示，寻找一题复测，解释首答和最近结果有什么区别。
4. 看完预写解析后自评，问有哪些标签不适用；不把愿意点「有帮助」当作理解证据。
5. 找到数据清除，先取消，再在仅测试数据中确认；问数据在哪里、是否同步。
6. 最后询问哪些信息有助于决定下一步，哪些令人困惑，不先问是否喜欢AI。

观察表：匿名编号、设备/宽度、任务完成情况、耗时、是否求助、停顿位置、对推荐的复述、演示/存储边界理解、退出意愿。人工记录，不声称已有自动埋点。

## 决策与后续

按METRICS中的候选门槛决定是否进入扩题。若主要阻碍为题量小，先寻求授权扩题和内容审核；若为推荐难懂，先改信息层次；若预写解析不足，才进入DECISIONS中的模型盲评。

任何学习效果验证都需新同构题、统一延迟窗口并控制难度；重复原题答对不代表迁移。未来对照固定顺序与规则推荐时，先制定随机顺序、排除演示和失访处理，再确定样本量。当前没有访谈纪要、实验报告或统计结论可展示。
