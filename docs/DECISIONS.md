# 产品设计决策与 AI 价值评估

所有用户问题和方案收益都是待验证假设。本文件由 AI 辅助整理；项目本人需在面试前亲自确认取舍。

## 设计决策记录

| 决策 | 理由与代价 | 何时重新考虑 |
|---|---|---|
| 保留原有原生 JS/CSS 与页面结构 | 原型小、运行无依赖；组件复用与大型状态管理能力有限 | 出现明确的维护瓶颈时，而非为求职堆技术栈 |
| 首答与最近结果并存 | 避免重做冲高首答率，也让纠错能影响当前建议 | 获得足够新题与延迟复测数据后再研究知识追踪 |
| 新题范围内用当前错题数与覆盖排序 | 修复永久困在历史薄弱点；可能推迟立即重复错题 | 观察用户是否需要切换为纠错优先；现在有复习入口 |
| 提交后再展示公式 | 减少提示污染独立首答 | 用户测试显示新手普遍无法开始时，考虑显式提示模式并标记提示使用 |
| 自评用固定标签且可跳过 | 有助复盘但不会假称自动识别错因；不支持开放文本 | 有证据表明标签不足，且有隐私与内容处理方案时 |
| 固定1/3天间隔 | 易解释、易验证；没有最优学习间隔证据 | 有足量授权长期记录及对照方案后 |
| 本地存储，无账户 | 降低演示摩擦和服务依赖；无法同步、可能被浏览器清理 | 真实需求与访问规模支持同步投入时 |
| 静态演示不调用大模型 | 可稳定公开，无 Key 和费用；展示不了真实生成效果 | 单独建立安全后端、鉴权、成本预算及评估后 |

## 大模型讲解是否有增量价值？

**当前结论：尚无证据证明有。** 12 道题已有预写解析。对于基础运算题，模型改写可能增加篇幅、延迟和成本，却未必改善理解。本轮保留可选本地接口，用于后续评测；公开演示明确禁用。

值得验证的场景：用户看完原解析仍不理解某个错误选项，需要另一种表达或迁移提醒。当前接口只接收题号和选项，没有开放追问、自由文档输入或个性化历史理解，不能把设想写成已实现功能。

### 候选评测方案（未执行）

1. 请具备相关教学经验的审阅者先独立核对全部预写答案与解题要点；当前未完成该审核。
2. 构造 12 题 × 4 选项共48个固定样本，记录模型/日期/提示词/输入/输出/耗时/用量。不采集个人历史，不用接口替身结果冒充真实输出。
3. 对照仅预写解析与预写解析加模型解释，盲评：答案一致性、推理正确性、是否回应所选错误、可读性、无臆测历史，各项0–2分。
4. 暂定进入小范围测试门槛：答案或核心推理严重错误为0；平均至少8/10；否则修提示、限制范围或删除功能。这是候选门槛，尚无达标结果。
5. 再对5位目标学习者观察理解和迁移到未见题的表现。候选体验预算：P95等待不超过10秒，单次成本上限由本人根据实际账户费用确定；当前18秒是请求超时上限，不是性能成果。
6. 若多数题无明显收益，公开版继续只用预写解析；不因名称中有「AI」而保留无价值调用。

接口只发送题目、选项、学习者选择、预写答案；忽略任意prompt和整段历史。响应按纯文本转义渲染。只有用户点击且本地配置后才发送。生成内容仍可能出错，规则校验不能保证教学正确性。
